# PineVision — Admin Pages Summary

All admin pages are accessible only to users with the **Admin** role. They provide system-wide visibility and management capabilities that are not available to regular client users.

---

## Admin Dashboard

**Page:** `admin/dashboard.html`

### Purpose
The central hub for system administrators. Provides a high-level overview of the entire platform's health and activity across all users and blocks.

### Main Functionalities
- Displays system-wide KPIs (total users, total scans, active blocks, alert counts)
- Shows recent scan activity from all clients
- Surfaces key system health metrics
- Provides quick-access navigation to all admin sections

### Key UI Sections
- Summary metric cards (users, scans, alerts)
- Recent activity feed
- Navigation sidebar to all admin pages

---

## User Management

**Page:** `admin/users.html`

### Purpose
Full lifecycle management of all user accounts on the platform.

### Main Functionalities
- View a list of all registered users with their role and status
- Create new user accounts (assign email, password, role, and permissions)
- Edit existing user details (name, email, role, permissions)
- Enable or disable user accounts
- Reset user passwords
- Assign roles (Admin or Client) and granular permissions

### Key Actions Users Can Do
- Add a new client or admin account
- Deactivate an account without deleting it
- Reset a forgotten password on behalf of a user
- Promote a client to admin or demote an admin

### Key UI Sections
- Users table with status badges (Active / Disabled)
- Add User modal/form
- Edit User modal/form
- Role and permission selector

---

## Flights & Scans (System-wide)

**Page:** `admin/flights-scans.html`

### Purpose
A system-wide view of all drone scan sessions performed by any client, giving admins full visibility into field activity across the entire platform.

### Main Functionalities
- View all completed and active scans across all users and blocks
- Filter scans by user, block, date, or status
- Review scan outcomes (bearing counts, percentages, duration)

### Key UI Sections
- Scans table with columns for user, block, date, duration, and results
- Filter/search controls
- Status indicators (Active / Completed)

---

## Alerts

**Page:** `admin/alerts.html`

### Purpose
System-wide alert monitoring. Admins can see all alerts generated by the detection system across every block and user, sorted by severity.

### Main Functionalities
- View all open and resolved alerts across the platform
- Filter by severity level: CRITICAL, WARNING, INFO
- Review alert details (which block triggered it, what threshold was breached, when it was created/resolved)
- Track auto-resolved alerts

### Key Actions
- Review critical alerts requiring immediate farm intervention
- Filter alert history by severity or status

### Key UI Sections
- Alert list with severity badges (Critical / Warning / Info)
- Alert detail panel (block name, description, timestamps)
- Filter controls by severity and status

---

## Reports

**Page:** `admin/reports.html`

### Purpose
System-level reporting and analytics for administrators. Covers all users and blocks rather than a single client's data.

### Main Functionalities
- Generate system-wide scan reports
- View aggregate statistics (total pineapples detected, bearing rates by block, trend data)
- Export data for external use

### Key UI Sections
- Report generation controls (date range, block, user filters)
- Summary statistics cards
- Data tables and trend charts
- Export buttons (CSV / PDF)

---

## Activity Log

**Page:** `admin/activity.html`

### Purpose
Provides a chronological log of significant user actions across the platform. Used for oversight, compliance, and troubleshooting.

### Main Functionalities
- View a timeline of user actions (logins, scan starts/stops, settings changes)
- Filter by user or date range
- Identify unusual patterns or unauthorized activity

### Key UI Sections
- Activity timeline/table
- User filter dropdown
- Timestamp and action type columns

---

## Audit Logs

**Page:** `admin/auditlogs.html`

### Purpose
A more detailed and structured audit trail than the Activity Log. Records system-level events for compliance and accountability purposes.

### Main Functionalities
- View detailed log entries for all system events
- Track who did what and when across the entire platform
- Supports accountability and regulatory compliance requirements

### Key UI Sections
- Detailed log table with event type, user, timestamp, and description
- Search and filter controls

---

## Admin Settings

**Page:** `admin/settings.html`

### Purpose
System-wide configuration panel. Controls platform behavior and thresholds that affect all users.

### Main Functionalities
- Configure alert threshold values (e.g. bearing rate % that triggers CRITICAL vs WARNING)
- Manage system-level preferences
- Potentially configure integrations (Firebase, MediaMTX endpoints)

### Key UI Sections
- Threshold configuration inputs
- System preference toggles
- Save/reset controls
